# 진로 나침반 설계

사용자가 제공한 최종 개발 인수인계서를 실행 기준으로 삼는다. Phase 1을 지금 구현하고 기초 조사 답변 및 문항 승인은 Phase 2 진입 조건이다.

## TCREI
- Task: 학생의 자기이해→학교 탐색→선택 이유→형의 수동 분석→게시 결과 흐름을 구현한다.
- Context: 기초 조사 답변 대기 중. 초기 개인정보는 형의 전달 정보이며 직접 응답이 아니다.
- Reference: 인수인계서, 공유 링크의 실제 읽은 내용, 공식 학교 자료만 사용한다.
- Evaluate: 빌드·도메인 테스트·브라우저 검증, 실제 연동과 미검증 범위 구분.
- Iterate: 문항 데이터와 버전을 분리하여 이후 승인을 받은 문항만 활성화한다.

## 구현 방식
요청된 React/Vite/TypeScript/Tailwind + Supabase Auth/PostgreSQL/RLS + Vercel을 사용한다. 서버 직접 구현이나 Sites 호스팅 대체는 사용자가 명시한 배포 방식과 맞지 않아 선택하지 않는다. 연결 정보가 없는 개발 환경에서는 합성 데이터로 UI를 확인할 수 있으며 실제 저장으로 표시하지 않는다.

초대받은 이메일·비밀번호 로그인. 공개 회원가입 UI 없음. 닉네임은 표시용. 관리자는 클라이언트 편집 불가한 private.admins 테이블로 지정하며 모든 RPC/RLS에서 검증한다. 테스트 구분은 trusted SQL provisioning으로만 설정한다.

## 화면
따뜻한 아이보리·초록 계열, 큰 한국어 글자, 모바일 하단 탐색. 시작/자기이해/학교 탐색/관심·비교/결과/관리자. 50문항 초안은 별도 JSON 버전이며 실제 학생 제출을 막고 테스트 계정에서만 제출 가능. 모르겠다는 독립 값 unknown. 서술형은 선택.

## 데이터와 권한
profiles, survey_versions, submissions(JSON 응답), schools, departments, favorites, reports. 제출과 결과 게시 상태 변경은 트랜잭션 RPC로 처리한다. 설문 버전은 첫 응답 이후 불변. DB에서 문항 수·응답 키·타입 검증. 보고서 초안 테이블과 게시본 테이블 분리: 학생은 게시본만 RLS 조회 가능. Markdown은 raw HTML 실행 없이 렌더링한다.

## 개인정보
실명·생년·주소·성적은 프런트엔드에 넣지 않는다. USER_PROFILE.md는 Git 제외. 원문 답변은 private 경로 제외. 공개 문서는 비식별 기준만 포함한다.

## 보류 및 외부 조건
최종 문항, 해석, 개인화 결과는 답변·사용자 승인 후. 실제 Supabase, GitHub 원격, Vercel 배포는 연결 가능 자격 증명 확인 후 진행. 자격 증명이 없다면 설정 문서와 검증 스크립트를 제공하고 실제 완료를 주장하지 않는다. 모바일 데이터 접속은 사용자의 실제 기기 확인이 필요하다.
