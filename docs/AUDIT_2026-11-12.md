# 프로젝트 전반 재검증 · 2026-11-12

## 구조와 검토 범위

React/Vite SPA의 App이 인증·사용자 세션·설문·관심·결과 상태를 관리한다. SurveyPage는 문항 표시/검토, SchoolsPage는 탐색/비교/관심, AdminPage는 원문/초안/게시를 담당한다. api.ts가 Supabase Auth/PostgREST/RPC에 연결하고 DB GRANT와 RLS가 최종 접근 권한을 검증한다. 문항은 버전으로 보존하며 비공개 보고서 초안과 게시본을 분리한다. Vercel은 정적 빌드를 배포한다.

검토: 소스 전체 주요 흐름, 승인50+5, 문항버전, 관리자/사용자 경계, 제출 잠금·재시도, 게시/취소, 마이그레이션, 학교 JSON 구조·공식 링크, Git 개인정보 제외, 빌드/운영 배포. 독립 코드 리뷰 후 수정분 재검토 완료.

## 발견 후 조치

1. 저장/최종 제출 대기 중 입력을 바꿀 수 있어 DB에 잠긴 답과 화면의 마지막 편집이 달라질 수 있었다. 입력·영역/검토 이동을 잠그고, 저장 상태를 App에 두어 화면을 나갔다 돌아와도 잠금 유지. 세션 토큰과 중복 저장 가드로 이전 계정의 늦은 완료를 폐기한다.
2. draft가 결과 화면에서 분석 대기처럼 표시되고 결과 새로고침이 미저장 답변을 초기화할 수 있었다. 제출 완료 상태에서만 결과 새로고침/학교 탐색 대기 안내를 제공하며, draft는 설문으로 돌아가 이어쓴다.
3. 두 관리자 탭에서 초안 저장과 게시 사이 다른 초안이 저장되면 미검토 본문이 게시될 수 있었다. publish_report(uuid,text) 단일 트랜잭션으로 요청자가 검토한 본문을 저장·게시한다. 종전 set_report_status의 publish 경로는 거부하고 새 편집 화면을 사용하도록 안내한다. 이전 관리자 탭은 새로고침 후 게시한다.
4. DB 테스트가 첫 마이그레이션만 실행해 이후 버전 누락을 놓칠 수 있었다. 모든 SQL 마이그레이션을 정렬 실행한 뒤 seed를 적용하도록 수정했다.

5. 검색/지원조건 필터 때문에 목록이 보이지 않아도 관심학교가 없다고 안내하던 문구를 수정했다. 빈 관심목록과 필터 결과0건을 구분하고 필터 초기화를 제공한다.

## 검증 결과

- Vitest18개 통과: 기존11개와 화면잠금/최종제출/화면왕복/네트워크 실패 후 재시도/작성중 결과/원자적 게시 호출 및 필터 안내7개.
- PGlite: 모든 마이그레이션, RLS격리·권한경계, 미승인 제출 차단, unknown·서술형 공란, 제출 잠금·멱등성·버전 불변, 초안 비공개·게시/취소·다른탭 초안 경쟁·구 게시 경로 거부·테스트 전용 삭제 검증.
- TypeScript/Vite production build 통과. JS 약650KB/gzip189KB로 번들크기 경고는 남아 있으며 빌드 실패는 아니다.
- 운영 SQL: migration003 적용. 트랜잭션 임시 자료로 게시/취소/재게시/비관리자 거부 검증 후 rollback. 함수 설치true, 검증자료 잔존false, 기존 제출1건 보존.
- 운영 실제 Auth/PostgREST: 테스트 계정 로그인·자기프로필만 조회·익명 개인정보 거부·초안 비공개·새 게시RPC 비관리자 거부·공개 학교11/과정22·승인v2/기존v1응답55개 보존 확인. 기존 응답과 보고서를 수정하지 않았다.
- 학교11개 ID와22과정 구조 검사; 학교홈/입학 URL18개 HTTP2xx 확인. HTTP응답은 모집요강 내용의 최신성이나 모든 교육과정 사실의 재검증을 의미하지 않는다.

## 남은 범위

실제 휴대전화 모바일 데이터 회선은 별도 확인이 필요하다. 학교 교육과정·실적·통학과 자료 내용의 세부 검증 상태는 SCHOOLS.md 기준을 유지한다. Auth 이메일 초대·비밀번호 재설정과 SMTP는 이번 기능 수정의 범위가 아니며 기존 운영 안내에 따라 설정해야 한다. 개인정보와 비공개 응답은 Git/배포에 포함하지 않는다.
